# Localization

The product catalog publishes Brazilian Portuguese at `aplicativos.html`, the existing app URLs, and localized static pages under `/<locale>/` for the other 15 locales. The previous homepage is preserved as `aplicativos.html`; existing localized `index.html` URLs remain product catalogs. The new commercial homepage and service pages are explicitly Brazilian Portuguese, not silently presented as translated content. Their catalog-language selector opens the corresponding product catalog. The language picker on app pages preserves the current app. Page translations, metadata, accessibility labels, app copy, and privacy-policy text are generated into `localized/`; visitors do not call an external translation service.

Supported locales: `pt-BR`, `en-US`, `es-ES`, `en-GB`, `es-419`, `de-DE`, `fr-FR`, `it-IT`, `pt-PT`, `nl-NL`, `ja-JP`, `ko-KR`, `hi-IN`, `id`, `tr-TR`, and `pl-PL`.

When Portuguese source copy changes, regenerate the static pages with `npm run localize` (requires network access to Google's translation endpoint), review the resulting legal and product text with fluent speakers, then run `npm run build`. The generated translations are stored in the repository so CI and visitors do not need translation-service access. In particular, privacy, advertising, permissions, and data-retention statements need human review before being treated as legally authoritative.

The generator reads `aplicativos.html` as the source for localized `index.html`. The digest retains the historical `index.html` identifier while hashing the unchanged catalog content; commercial-home copy does not invalidate product translations. The build adjusts catalog hreflang to the Portuguese catalog URL, normalizes deployment URLs, fixes legacy anchors, and prerenders app data in the published HTML. Edit source files, not `dist/`. See `README.md` for configuration and publication.
